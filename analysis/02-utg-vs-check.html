The first notebook looked briefly at the actions of a BB caller to an UTG preflop raiser, where the BB player is first to act on the flop. But the BB player hardly ever will lead with a bet in this situation, regardless of the flop.1

In this workbook we look to see how UTG responds to the almost-certain check by the BB player.

Clustering variables when there are multiple betting options

In the last notebook, we mentioned the difficulty that comes with using the raw probabilities from each of the actions as variables to perform clustering over an array of variables that sum to one. A change in one of these variables necessarily produces a change in the other variables. One way to diminish the effect of that is to take the square root of the probabilities. With only two betting options for the BB player (checking, and betting 4.5 big blinds), we were easily able to transform the d variables into a d-1 space, using a reference variable.

But here our UTG player has three betting options: check; bet 3 big blinds, and bet 5.9 big blinds. A more generalizable approach would be needed if we begin to give the solver 3 or more options at each node. I created compositional.R, which is an attempt at doing just that. It defines a function, add_compositional_distance(), which does two things: * for each action other than Check (e.g., each betting option), it creates a column representing the ratio of the square root of the percentage of time the action is taken to the square root of the percentage of time the Check action is taken; * calculates the Mahalanobis distance for each flop, relative to the other flops in the dataframe, based on the ratios above.

Mahalanobis distance measures how far a point is from the center of a distribution, accounting for the correlation structure of the variables. It is expressed in units of standard deviations.

Low values (close to zero) indicate the observation (the set of betting choices the solver arrived at for the flop) is similar to the typical observation in the distribution, indicating similarity between with other flops.

High values indicate the observation is far from the typical observation, indicating dissimilarity between the flop and other flops.

In other words, the Mahalanobis measure captures how unusual a flop’s strategy is, compared to the other flops. This might suggest these are worth study as outliers or strategic exemplars.

Choosing the clustering variables

The function above generates three variables (the transformed Bet 3 variable, the transformed Bet 5.9 variable, and the Mahalanobis distance measure) that we could choose to include as variables in our clustering algorithm, in addition to the EV and Equity variables. We almost certainly want EV and Equity to be two of our clustering variables.

Since we can only represent clusters visually in a three dimensional space, there is some attraction to the idea of using three clustering variables. With two of them sorted out, using the Mahalanobis measure is tempting, as it is a function of the transformed Bet 3 and Bet 5.9 variables. Additionally, it represents how unusual a flop is compared to the other flops in our database. But I think there’s a downside to using it as a clustering variable. First, it collapses some of the betting nuances down to a single number. If a flop is bet for the high bet amount a large percentage of the time, we want to know that, and we probably want to cluster similar flops together with it. So using something closes to the original betting frequencies, such as the transformed Bet 3 and Bet 5.9 variables, makes more sense as clustering variables. If we want to group flops by how unusual they are because we want to study them more closely than others, we can simply sort the table by Mahalanobis distance.

One other possibility is that we cluster using EV, Equity, the transformed betting frequencies, and the Mahalanobis distance. But because the Mahalanobis distance is a function of the transformed betting frequencies, I am hesitant to do so.

(But why not cluster with Mahalanobis distance as well?)

We can now start clustering these flops together using K-means. We’ll try a few different options of K to see what makes sense, but start with K = 3.
